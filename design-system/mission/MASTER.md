## Global tokens and decisions
Opaque matte molded surfaces; 3px light rims, 24px cards and 16px controls; double inner/outer shadows, 180ms tactile press feedback. Indigo shell, cream content, mint/blue/coral/lilac accent blocks. Text: dark #19213b, muted #44526a, white on dark blue #1d62c9 and indigo #263fa0. Canonical variables in docs/style.css. Use semantic priority labels and counts rather than color alone. No backdrop blur, glass refraction, external fonts, CDN or third-party runtime. System font with Thai fallback; light color scheme with dark decorative shell, not a separate dark mode.

The style catalog cautions against playful clay in data-critical interfaces. Use cream data surfaces and static wallpaper to preserve clarity; prefer 8/16/24px spacing for dashboard density rather than the catalog's marketing-style 48px gaps and continuous background animation. Do not animate cards on idle. Respect reduced motion, keyboard focus, native controls, 44px targets where practical, and responsive wrapping. Decorative shapes and icon tiles must never obscure data.

## Layout
Login: deep indigo hero, local original clay bento SVG, cream token form. Workspace: solid sidebar with selected blue block, compact toolbar with period/repository filters, Manage repositories, Refresh and actual account sign-out. Overview uses color-coded KPI blocks. Dashboard: 12 columns, three KPI blocks; timeline spans 7 and daily chart 5 on wide desktop; lower four cards span 3 each at 1440px+, 6 each at smaller desktop, stack on mobile. At narrow widths timeline and trend stack, table scroll stays local to table; keyboard and touch drill-down remain. Use rank badges, sample-based priority percentages, daily event totals and selected-cell activity chips derived from real sample; preserve scope/partial flags. No fabricated comparison metrics, milestones or completion percentages.

## Security and checks
Static vanilla JS and GitHub Pages remain. PAT, API client, CSP and analytics model are unchanged. Keep token in memory, local assets only, no added API requests. UI tests cover DOM IDs, unchanged safe rendering, design tokens, sampled contrast, responsive layout contracts and session reset. Real PAT login and full visual verification require separate validation.
