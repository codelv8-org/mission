# Mission — Orbit Timeline UI / Modern Analytical Workspace

## Main visual direction (approved prototype V3)
Orbit Timeline UI is the primary visual reference: Modern Dark SaaS Dashboard, Bento Summary Cards, multi-repository Interactive Gantt-style Calendar, double-layer pill-shaped activity bars, collapsible workstream groups, sticky timeline labels, participant initial stacks, compact detail panel, minimal data-dense layout. Dark canvas #111215, card #18191e, task surface #202127, grid #2d3039. Timeline colors: milestones #7163f5, issues #0dba89, pull requests #229ce9, commits #ef8a3d. Light/System supported. Canonical implementation: `docs/orbit.css`, `docs/orbit-model.mjs`, `docs/orbit-view.mjs`. Existing Mission shell, PAT entry, analytics and export are retained. No remote fonts, libraries, image requests or inline style attributes. Initials avoid additional avatar network requests.

## Data and interaction contract
Use existing session-only GitHub client and up to 20 selected repos. Group by repo or activity. Quick repo chips synchronize the global filter; the topbar `select#period` is the sole calendar range for Orbit, Activity Matrix, Activity Log and Timeline KPI/chip counts. Last 7/30 days and Last Month use daily buckets; Last Year uses monthly buckets; the window ends on the snapshot calendar day. No independent range or prev/next controls. Due dates beyond the range are clipped with continuation markers and remain visible in details. Actual issue and PR lifetimes (open through snapshot, completed/closed/merged using observed timestamps), commits on their committer date, milestones due dates when set. Status pills do not imply numeric progress. Only closed/total milestone issue counts provide numeric fill; no due date or zero tasks must not fabricate a plan or completion. No drag/resize in read-only GitHub mode. Show partial history and endpoint/cap warnings; 100 initial rows with Show more. Use safe text nodes and fixed GitHub HTTPS links. Snapshot copies only the current visible rows and details, including passive bars, with no interactive controls or PAT. Clear all timeline state on logout, repository selection change and pagehide.


## Direction
Selected by the user after testing claymorphism, liquid glass and neo-brutalism. Combine Swiss Modernism 2.0, Linear-inspired minimalist developer workspace, Data-Dense Dashboard and adaptive 12-column Bento Grid. Source: [UI UX Pro Max style catalog](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/a4fc248f6136552cb881e298847abc7ddce84e6b/.claude/skills/ui-ux-pro-max/data/styles.csv), IDs minimalism-and-swiss-style, swiss-modernism-2-0, data-dense-dashboard and bento-box-grid. The catalog recommends dense grids for analytics and warns about relying on Bento for dense tables; combine compact cards with native scrollable tables. Applied the reviewed catalog directly, not the unavailable Python generator.

## Layout and behavior
Flat attached left navigation and thin toolbar; compact app shell. Dashboard is the default, first menu, with three KPI cards, full-width activity trend and four lower analytic cards at 1440+, then two or one responsive columns. No Overview or Timeline sections on Dashboard. Timeline exclusively contains full-width Orbit, Activity Matrix and Activity Log, with the shared global Period. Native table scrolling and sticky headers retained; compact desktop targets with 44px touch targets. Six analytic cards expand inline to full grid width (one at a time), accessible controls and reset on session/data reset. Real daily sparklines for active-project counts and observed events from the same loaded snapshot and selected period/repository scope, independent of the event-type filter; no issue-history sparkline because only a current snapshot exists. Existing tooltips/drill-down and partial-data semantics preserved. No invented trends or percentage deltas.

## Verification

## Calendar periods
Asia/Bangkok (ICT) calendar boundaries; date series anchored to the last successful load. Last Month: first of previous month through today, daily; Last Year: January 1 of previous year through today, monthly. Daily column date + Thai weekday, weekends tinted independently of heat levels; month groups span exact day counts using colspan and colgroup, sticky row headers, no grouped row in monthly mode. Daily/monthly chart, sparklines, event drill-down and export share the period. Extended loads have explicit bounded pagination and partial states, not complete audit histories. Current open-issue snapshot does not change with time filters.


## Developer Intelligence / Analyze
Use Orbit surfaces, existing semantic theme tokens and a responsive 12-column bento. Analyze is third navigation item; Performance is fourth; Dashboard remains landing. Performance KPIs and daily/monthly plots use the same global Period and Repository scope. Only observed merged_at, completed issue closed_at, default-branch committer dates and terminal workflow updated_at count. Median requires valid creation/merge pairs; workflow success denominator is all known completed outcomes; undefined ratios are em dash. WIP is a current sampled snapshot. Technology Footprint and evidence radar describe current selected repositories: GitHub language bytes and exact root-level marker presence; denominator is scanned repos, not person ability. Do not retrieve file contents or infer framework versions, personal skill scores or agent identity. Explicit coverage, no remote assets, no inline style, no credentials or persistent data. Clear Analyze on session and repository changes; snapshot exports only visible view.


## Contribution and historical comparison
Add the contribution and comparison cards beneath Skill Evidence, using Orbit accent tokens and responsive tables. Global period/repository scope remains authoritative; local activity/contributor filters affect only contribution cards. Count commit and merged-PR records separately. Use GitHub-linked author/PR creator and explicit terminal AI-Agent trailers or ai-agent labels with a fixed provider vocabulary. Unknown markers, multiple declarations, bot accounts without provider declarations and unattributed records must remain distinguishable; never infer Human from User or a provider from login substrings. Show declaration evidence and safe source links, not message bodies or email addresses. Comparison is a previous equal elapsed-duration ICT window, uses bounded optional historical loading through the existing fixed-origin client, and suppresses deltas for incomplete or undefined measures. No historical skill estimates, CI attribution without linkage, or persistent storage. Session reset clears contributor filters and comparison history preference. Export preserves current rendered values/scope, omits local controls.


## Engineering Insights & Recommendations
The Analyze page opens with a compact four-card summary and responsive evidence/action cards. Order Act, Review, Verify, Observed, then repository/key; this is deterministic rule ordering, not employee or project risk ranking. Use visible counts, data coverage, explicit time basis, limitations and same-repository safe GitHub links. Current queue/root snapshot remains distinct from period-scoped history. Review thresholds: open PR >=7 full days using created_at only; median creation-to-merge >=72 h with >=3 valid PRs; comparable +24 h cycle / -10 pp success changes. Rule matches do not imply an SLA breach or quality/proficiency. Practice review excludes unreadable/capped root scans and never treats missing markers as absent practices. No additional network requests or LLM. Filter/pagination are local, reset on session/repository changes, export only rendered findings without controls.
