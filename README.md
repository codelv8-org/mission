# MISSION — GitHub Pages PAT Edition (v0.5.1)

Developer Mission Control. **GitHub only**: GitHub Pages hosts the frontend; the browser connects directly to the official GitHub REST API using the user's fine-grained personal access token. No backend, Worker, aaPanel, OAuth app, database, external dependencies or external deployment.

## Start
1. Generate a fine-grained PAT: https://github.com/settings/personal-access-tokens/new .
   - Token name: Mission Read Only.
   - Expiration: 30–90 days (or shorter).
   - Resource owner: the account or organization whose private repositories you want to monitor.
   - Repository access: Only select repositories; choose the intended repositories.
   - Repository permissions (read-only): Metadata (mandatory), Contents, Issues, Pull requests, Actions. No other permissions; no write access. Organization approval may be needed.
2. Open https://codelv8-org.github.io/mission/ . Verify the URL before entering a credential. Enter the PAT directly on the Mission page, not into chat, GitHub files, Actions secrets, or a URL. Click Connect GitHub.
3. Mission verifies /user and discovers repositories through /user/repos. It initially monitors up to eight recently pushed repositories; use Manage repositories to choose up to 20 or add an accessible owner/repo manually. Select Apply & load.

No build step or setup variables. The Pages publication source is main /docs. If Pages was disabled, enable it in Settings > Pages.

## Features
- **Project timeline (Orbit):** exclusive to Timeline navigation. Dashboard is the first menu and default after connection; Overview has been removed. Uses the existing 20-repository picker, quick repository chips, grouping by repository or activity, type/status/search filters, the shared topbar Period selector (Last 7 days, Last 30 days, Last Month, Last Year), collapsible rows, participant initials and GitHub detail links. Issues and PRs show observed creation-to-close/merge or snapshot lifetimes, commits are point events, and milestones use explicit due dates when present. Only milestone closed/total issue counts are shown as percentages; other rows use actual state labels. No scheduling edits or invented progress. At most 100 milestones per repo per refresh; cap/errors remain visible. Orbit, Activity Matrix, Activity Log and timeline summary counts share the global calendar period; there is no local date navigation. Open counts show the current state of loaded items whose lifetimes overlap the period, not historical open counts. Planned due dates beyond today are clipped to the selected range and remain visible in item details. Initial render limits expanded rows to 100; Show more reveals additional rows. No credentials stored.
- Download HTML: after a successful load, export the entire current view (including scrollable rows, charts, chosen filters and selected-day detail) as a single static report with the current theme, fetch time and export time. No additional GitHub API requests, login form, account controls, PAT, scripts or offline cache. Only the currently rendered view is exported, not hidden views or raw API data. The file may contain private repository information: confirm the warning, protect the unencrypted file, and delete it when no longer needed. GitHub links require internet/appropriate GitHub access; the report itself opens locally without internet. The report does not refresh or re-filter.
- Dashboard (analytics bento): daily/monthly stacked activity, priority distribution, most-active projects, attention queue, and latest workflow signals. Uses only the already loaded sample; no extra API calls. All periods use Asia/Bangkok calendar boundaries ending at the snapshot time: Last 7/30 days show daily columns, Last Month runs from the first day of the previous calendar month through today, and Last Year runs from January 1 of the previous calendar year through today with monthly columns; issue metrics are the current open-issue snapshot. Asterisks and question marks flag incomplete sections; no record is not proof of inactivity. PR, issue and workflow dates in the Activity Matrix reflect latest updates of loaded records, not a complete event history; Orbit uses separate observed lifetimes and due dates.
- Navigation: Dashboard, Timeline (Orbit + Activity Matrix with event drill-down + Activity Log), Priority Queue (labels P0–P3 and blocked), Repository Portfolio.
- Automatic discovery of up to five pages (500 results); manual additions verify access with GitHub.
- User identity checked on connection and every dashboard refresh.
- Bounded history: initial 7/30-day sample keeps the existing caps (10 commits, 30 issue/PR results, 10 PRs, 5 workflows per repository); extended periods fetch up to 3 pages × 100 per activity endpoint for Last Month and 5 × 100 for Last Year. Open issue snapshot remains capped at 100 issue/PR results. Cap hits and failed sections are marked partial. GitHub workflow retention, default-branch commit scope and latest-update semantics mean these are not complete activity histories. No persistent cache. Daily timelines show Thai weekday abbreviations, weekend highlighting and month colspan groups when crossing months. Year view uses one column per month with year labels.
- GitHub API GET only; no mutations. Rate limits and permission failures can affect results.
- Session is memory-only, clears on sign-out, page reload/navigation or after one hour. No token/data in localStorage, sessionStorage, IndexedDB or URL. The explicit HTML export writes only displayed report data to a user-selected download; no PAT or raw API response is embedded. Reconnect with another token for a different resource owner; only one token is active at a time. Public repositories can be visible even if not selected for private-repository access.

## Security
The PAT is a powerful bearer credential. Generate a short-lived read-only token with minimal repository access. Mission itself is a public static shell, not a server-side website access gate; GitHub authorizes data access. The app cannot prove that the supplied token has no write privileges, so the user must choose read-only settings. A compromised frontend, browser extension or untrusted same-origin site could access browser memory or requests; protect main and consider a dedicated trusted origin for sensitive use. See SECURITY.md. Local logout does not revoke the PAT; revoke it in GitHub Settings if needed.

## Tests and publication
`npm test` with Node.js 22+ (no npm install needed). GitHub Actions tests changes; Pages automatically publishes via its existing branch source setting. Tests use mocked GitHub API responses, not real PATs.
