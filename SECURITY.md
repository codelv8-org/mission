# Security — PAT Edition

- Trust boundary: GitHub Pages is public and the browser holds the supplied PAT in memory. The site cannot implement a real server-side allowlist or prevent a user with a valid PAT from loading their own data. GitHub enforces repository authorization. No shared credential or private snapshots are published.
- Use only expiring fine-grained PATs scoped to selected repositories with read-only Metadata, Contents, Issues, Pull requests, Actions. Never paste a PAT into chat, source code, Actions secrets, logs, a URL or a third-party site. The application checks format, not read-only scope; permissions must be configured in GitHub.
- All API traffic is fixed to HTTPS api.github.com using GET, Authorization header, no redirects or browser credential cookies, and no-store. CSP restricts connections to that origin and scripts/styles to the same origin; no external scripts or dependencies. Upstream text is rendered via textContent; outbound links limited to HTTPS github.com.
- Token/data are not written to browser storage. Sign out, pagehide or one-hour local timeout clear session and displayed data, and dashboard requests are aborted. In-flight manual lookup may complete but its result is ignored after logout. Local logout does not revoke the PAT. Revoke in GitHub if suspected compromised. Avoid untrusted extensions and other untrusted apps sharing the github.io origin. Browser password managers may have independent behavior; do not save PAT as a password.
- Protect main and review changes to the static frontend and CI. No PAT is needed for CI. Mocked tests cover URL confinement, GET-only, identity, discovery, pagination, priority, permission errors and revocation. Real browser/PAT flow and organizational approval must still be tested by the user.
