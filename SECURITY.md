# Security
- GitHub App user authorization with exact callback, random state and S256 PKCE. Temporary state/verifier in sessionStorage is removed before exchange. Tokens are not stored in browser storage. Never enable GitHub device flow or embed a client secret on Pages.
- Worker validates exact CORS origin, requires configuration and explicit GitHub account allowlist (numeric IDs preferred). It exchanges only GitHub authorization codes using the server secret. It requires an expiring GitHub App user token. No shared PAT, installation private key or broad OAuth repo scope.
- AES-GCM session encryption uses HKDF of the GitHub client secret, unique random nonce and app-bound authenticated data. Session TTL up to one hour; secret rotation invalidates all sessions. The Worker checks current /user and allowed identity on every data request. Browser receives an opaque session bearer only; local logout clears memory, not the GitHub authorization; revoke app authorization on GitHub to terminate access server-side. Never log session/auth request bodies, tokens, or private repository contents.
- GitHub App permissions must all be read-only and installations limited to intended repositories. Fixed GitHub API routes, no arbitrary proxy, no mutations. Discovery and explicit monitoring are bounded. Upstream errors are visible; no-store responses.
- Public Pages assets remain public. Any other untrusted site hosted on the same origin may weaken browser isolation: use a dedicated origin for production. GitHub Pages cannot itself authenticate a public site. Protect main/workflow writes. Rate-limit Worker endpoints for production if needed.
- Real deployment release checks: exact callback URL and app permissions, authorized user, unauthorized user, invalid/expired session, app uninstallation/revocation, correct repositories and no secret leakage. Unit tests mock upstream; no real OAuth flow has been tested until configured.
